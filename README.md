## Selected work

### 📝 MCQ Exam Builder

A professional assessment workflow for educators: import question banks, review and validate questions, generate shuffled exam versions and produce answer keys.

**Why it exists:** exam preparation is frequently fragmented across Word, Excel and text files, creating avoidable manual work and opportunities for error.

**Design priorities:**
- robust multi-format question import
- validation before exam generation
- reproducible shuffled versions
- educator-focused UX
- privacy-conscious processing
- no external AI processing of exam content

**Status:** active development and production deployment; repository currently private while it undergoes release-quality review.

---

### 📞 [Voicemail SMS Auto Reply](https://github.com/christosdvm/Voicemail-SMS-Auto-Reply)

An automation workflow designed for professional practices that converts voicemail notifications into controlled SMS follow-up during defined operating hours.

**Why it exists:** clinicians and small practices cannot always answer calls while consulting, teaching or working with patients. A missed call should not automatically become a poor client experience.

**Engineering themes:** Gmail automation · SMS APIs · business-hours logic · duplicate prevention · privacy-by-design · operational reliability.

---

### 📊 Veterinary Logbook & e-Portfolio

A structured competency-tracking framework for veterinary students, designed around longitudinal clinical-skills progression rather than a static checklist.

**Direction:** evolve student-level evidence and dashboards into programme-level analytics across successive years of veterinary training.

**Product themes:** competency tracking · structured data · student dashboards · curriculum analytics · quality assurance.

## Engineering & product principles

```text
Start with the workflow, not the technology.
Automate repetitive work without hiding important decisions.
Design for the professional who actually has to use the system.
Make privacy and data handling explicit.
Ship, observe real usage, improve, repeat.
```

I am interested in software that survives contact with real users — not just prototypes that work in a controlled demo.
